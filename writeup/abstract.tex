Federated learning (FL) allows clients to collaboratively train a model without centralising their data. As FL training is often deployed across distributed edge environments, realistic FL deployments are shaped by differences in processor speed, memory capacity, network conditions, and data. This dissertation evaluates FL methods from a deployment-aware perspective: measuring not only model performance, but also wall-clock time, client trips, staleness, submodel quality, parameter coverage, and slow-client fairness.

To make these effects measurable, this dissertation develops \texttt{fedctl}, a command-line framework with a browser-based interface for submitting, deploying, monitoring, and retrieving Flower experiments on a real heterogeneous Raspberry Pi cluster with \(30\) \texttt{rpi4} and \(20\) \texttt{rpi5} workers. \texttt{fedctl} enables reproducible control over heterogeneous client placement and network impairment and exposes detailed runtime system metrics; this allows for comprehensive evaluation of FL methods under realistic deployment conditions.

Using \texttt{fedctl}, the dissertation evaluates \textbf{submodel FL}, \textbf{asynchronous FL}, and their combination, \textbf{asynchronous submodel FL}. Under \textbf{compute heterogeneity}, submodel FL provides a practical solution for weak clients instead of excluding them or forcing infeasible full-model training: \texttt{HeteroFL} and \texttt{FedRolex} give clear wall-clock savings, while \texttt{FIARSE} further improves submodel quality. Under \textbf{straggler-induced heterogeneity}, asynchronous FL allows more flexible training schedules: \texttt{FedAsync} is fast in mixed-device settings, \texttt{FedBuff} improves learning stability through buffered aggregation, and \texttt{FedStaleWeight} improves slow-client influence.

This dissertation proposes \texttt{FedCover}, a coverage-aware aggregation algorithm for asynchronous submodel FL. The evaluation first shows that direct \texttt{FedBuff} and \texttt{HeteroFL} composition is feasible, but stale partial updates lead to server-side parameter coverage instability. \texttt{FedCover}'s inverse-coverage correction is then shown to address the problem and improve time to target.
